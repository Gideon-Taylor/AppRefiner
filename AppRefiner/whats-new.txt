VERSION 1.4.0
=============

*** PLEASE READ: RESTART APPLICATION DESIGNER ***
-------------------------------------------------

This release updates the AppRefiner integration running inside Application
Designer. Close and reopen any Application Designer that was already open —
until you do, the new definition-name and annotation suggestions won't appear.


FAR FEWER FALSE ERRORS IN RECORD, FIELD AND COMPONENT CODE
----------------------------------------------------------

Several cases where AppRefiner reported errors in valid code that uses
records, fields and component interfaces are fixed. Component- and
record-heavy programs should show far fewer false reports.

• REC.FIELD as a Field-Name Argument - Functions that take a field name, such
  as GetNextNumberWithGaps(REC.FIELD), accept a bare REC.FIELD, as the
  compiler does. AppRefiner used to report it as the wrong parameter type.
  These parameters now accept REC.FIELD and Field.X, and check the field's
  data type where the parameter requires one. Market.GBL is read as a
  REC.FIELD reference, as the compiler reads it.
• Records Returned by Your Own Functions - A user function or method declared
  Returns Record was assumed to return a record named after its arguments or
  the program's default record, which led to false member errors on the
  result. Only builtin functions such as CreateRecord(Record.JOB) and
  GetRecord() name the record they return now.
• Reassigned Record and Field Variables - A Record, Field, ApiObject or any
  variable used to keep the first type assigned to it, so members of a
  different record assigned later were reported as errors. Now the latest
  assignment decides. Assigning a different API object to an ApiObject
  variable no longer gives a false "Cannot assign" error, and variables
  declared any accept any value.
• Component Interface Properties and Items
  - A CI's keys and fields are valid properties: reading or setting
    &ci.EMPLID is no longer reported.
  - Collection items are typed as DataItems instead of Rows, so their fields
    aren't reported either.
  - Unknown methods are no longer reported on a CI, since a CI can define its
    own.
  - An ignored return from an API object method is no longer an error,
    matching App Designer.
  - With a database connection, named CIs are now checked against their real
    definition (see Component Interface Typing below).


NEW FEATURES
------------

• Type Annotations for ApiObject - PeopleCode makes you declare API objects as
  plain ApiObject, so AppRefiner couldn't check what you did with them. You
  can now name the real type in a /* as T */ comment, and AppRefiner types
  and checks the variable as that type. App Designer treats the annotation as
  an ordinary comment.
  - Annotate a declaration (Local ApiObject /* as Session */ &s;), a
    parameter (&f As ApiObject /* as Folder */), a property, an instance
    variable or a method's return type.
  - Annotate an assigned value: &f = &s.GetFolder() /* as Folder */;
  - Annotate Record and Field declarations with a specific definition
    (Local Record /* as Record.JOB */ &r;), and any with any of these types.
  - Annotations on method headers apply to callers and are inherited by
    overriding methods.
  - AppRefiner warns when a call passes a different API type than the
    annotated parameter expects, or when an initializer or later assignment
    contradicts the annotation.
• ApiObject Types Worked Out Without Annotations - Most ApiObject variables
  now get a type even with no annotation:
  - From how the variable is used: it takes the one API type that has every
    member you use on it. A use that doesn't fit is a single warning instead
    of a member error.
  - From what a method returns: a method or function declared to return
    ApiObject, Record or Field takes the type its Return statements agree on,
    including calls between methods in the same class and in other programs.
    A warning shows when the returns disagree.
  - From assignments: properties and instance variables are typed from their
    getters and from what is assigned to them.
• Component Interface Typing - A CI named with CompIntfc.X (in GetCompIntfc()
  or an annotation) is read from the database and checked against its
  definition.
  - Its properties, collections, items, and custom and standard methods are
    typed and checked. Find() returns a collection of the CI's instances, and
    Item() on that collection is the CI. CI items accept their own fields and
    collections, plus ItemNum.
  - Autosuggest lists a CI's members, hovering a CI property shows its type,
    record field, read-only flag and comment, signature help shows the CI's
    custom methods, and Go To Definition opens the CI's Methods PeopleCode at
    the function.
  - The new "Refresh Component Interface Cache" command re-reads cached CIs.
    Saving a CI's PeopleCode refreshes that CI automatically.
• Definition Name Suggestions - Type a reference keyword, a dot and at least
  one letter, and AppRefiner lists matching definition names from the
  database. For example, HTML.Z lists HTML definitions starting with Z.
  - Supported keywords: Record, Field, Page/Panel, Component/PanelGroup,
    CompIntfc, HTML, Image, StyleSheet, SQL (standalone SQL only), MenuName,
    Message, FileLayout, Node and Operation.
  - The list holds 500 names at a time and is re-queried as you type, so
    large databases are fully reachable. Ctrl+Space reopens the list.
  - Needs a database connection.
• Annotation Type Suggestions - Typing "/* as " where an annotation applies
  lists the types that fit there: the ApiObject subtypes, plus CompIntfc.,
  Record. and Field. entries that lead straight into definition name
  suggestions. No database connection needed.


IMPROVEMENTS
------------

• Hovers Show Refined and Annotated Types - Hovering a variable shows the type
  AppRefiner worked out for it and where that type came from, on its
  declaration, on a parameter, and on an assignment target (where it shows the
  type just assigned). Signature help shows annotated parameter and return
  types.
• Builtin Method Hovers for Every API Type - Methods of every builtin type now
  show their signature and return type on hover; this used to cover only about
  a dozen types. Hovering a method name in a call shows the call's real return
  type instead of "any".
• Array Checks - Push, Unshift, Find, Substitute and Replace arguments are
  checked against the array's element type, including in multi-dimensional
  arrays, and errors name the expected type. &arr.Len and &arr.Dimension are
  typed as number.
• Every Type Error Is Reported - A line with several type problems now shows
  all of them instead of only the last one found.
• Warning Squiggles Are Amber - Compiler warnings used to be light green, and
  the unimplemented-abstract-members squiggle rendered purple.


BUG FIXES
---------

• Short Class Names in the Program Being Edited - The program being edited can
  refer to classes by their short names (App Designer expands them when it
  saves). AppRefiner now expands them through the program's imports the same
  way. PKG:Config and OTHER:Config are no longer treated as the same class,
  and with a short "extends Base", inherited members, %Super autocomplete, the
  abstract-member checks and quick fixes, and the class hover find the right
  base class.
• Missing and Ambiguous Imports - "import PKG:Config;" no longer counts as
  importing ZZ_AR_DEMO:Config. Every class reference is checked, including
  Locals, parameters, return types and properties, so an ambiguous short name
  is reported the way App Designer reports it on save. The quick fix offers
  the exact import needed.
• Wildcard Imports Without a Database - Without a database connection, every
  class under "import PKG:*;" was reported as not imported.
• Arrays of App Classes - An array of a subclass is no longer accepted where an
  array of its base class is expected; App Designer rejects it too.
• Java Objects - Methods and properties called on a JavaObject (from
  CreateJavaObject, GetJavaClass and so on) or a plain object are no longer
  reported as unknown. They belong to the Java class, which AppRefiner can't
  see.
• Optional Parameters - CreateProcessRequest's parameters are now optional.
• Rowset.SelectNew - Now known. It used to be reported as an unknown method.
• NoExport Function Headers - Function headers marked NoExport now parse.
• SQL Error Dialog on SQL Server Through the App Designer Proxy - Connecting
  through the App Designer Proxy on SQL Server no longer makes Application
  Designer show a SQL error ("Conversion failed when converting the nvarchar
  value ... to data type smallint") while reading the tools version.
• Ctrl+Space After a Partial Member Name - At &obj.Us, Ctrl+Space now reopens
  the member list filtered to "Us". It used to show nothing.


VERSION 1.3.3
=============

*** PLEASE READ: RESTART APPLICATION DESIGNER ***
-------------------------------------------------

This release updates the AppRefiner integration running inside Application
Designer. Close and reopen any Application Designer that was already open —
until you do, the new App Designer Proxy connection and the fixes below that
depend on it aren't active.


NEW FEATURES
------------

• App Designer Proxy Connection (EXPERIMENTAL) - A new Database Type in the
  Connect DB dialog runs AppRefiner's queries through the session Application
  Designer is already signed on with. AppRefiner itself opens no database
  connection and needs no database credentials. This connection type is still
  experimental: if you see problems, switch back to an Oracle or SQL Server
  connection, which work as before.
  - Queries travel over a private channel between AppRefiner and the
    AppRefiner hook inside Application Designer. It has no name, so no other
    program can find it and connect, and only that channel can submit queries.
  - Before a query reaches the database, the hook checks that it is a single
    SELECT statement. It rejects anything else: other statements, a second
    statement after the first, comments, row locking (FOR UPDATE), SELECT
    INTO, data-changing or administrative keywords, and any Meta-SQL other
    than a short list of read-only functions. The whole check is one short
    file you can read for yourself, AppRefinerHook/SqlProxySqlPolicy.cpp:
    https://github.com/Gideon-Taylor/AppRefiner/blob/1.3.3/AppRefinerHook/SqlProxySqlPolicy.cpp
  - The hook caps each query at 10,000 rows, 64 bind values and 8,192
    characters per column.
• Cancel the Auto-Connect - When saved settings let the Connect DB dialog
  connect on its own, it now counts down for 3 seconds first. Click anywhere
  or press a key to stop it, for example to untick Save Password.
• Forget Saved Credentials - A new command, "Database: Forget Saved
  Credentials", forgets the saved password for the database you are connected
  to, so it stops connecting automatically. Other databases are left alone. It
  is only available while a connection is active.
• Delete Import Quick Fix - Unused and duplicate imports now offer "Delete
  unused import" or "Delete duplicate import" from their indicator.
• ComponentLife Variables - ComponentLife declarations are now parsed and
  recognized as their own variable scope instead of being treated as
  Component.


IMPROVEMENTS
------------

• Event Mapping Annotations Stay Put - Event Mapping and Event Map Xrefs text
  no longer disappears a moment after a program opens, after an edit, or when
  you run lint. A lint message on the same line now appears alongside the
  event mapping text instead of replacing it.
• More Precise API Object Types - CI, Portal, Query and Repository API objects
  are now typed as their specific kinds, so member checks and hovers are more
  accurate. Builtin type names display in PascalCase.
• Faster Hovers on App Classes - App class source and existence lookups are
  cached per connection and refreshed when you save, cutting repeated database
  round-trips.
• Parameter Hints Line Up - Parameter inlay hints are positioned correctly on
  lines with non-ASCII characters, and arguments that start with @ no longer
  show a gap after the label.
• Lighter Autocomplete - Signature and system-variable suggestions only run in
  PeopleCode editors, and collecting variables for autocomplete no longer
  queries the database.


BUG FIXES
---------

• "Not All Paths Return" on Stacked When Clauses - An Evaluate where every arm
  returns is no longer flagged when several When lines share one body. Convert
  If/Evaluate also no longer mis-converts these (issue #79).
• Builtin Functions Flagged as Unknown Fields - In record PeopleCode, builtin
  function names were mistaken for field names and reported by the 1.3.2
  unknown-field check.
• Dialogs That Couldn't Take Keyboard Focus - Better Find and the diff dialogs
  are now owned by the Application Designer window, so they get focus under a
  strict foreground lock, as seen on Windows Server 2022 terminal servers
  (issue #77).
• Function Cache Error on Record Field Programs - Incremental cache updates
  used a different path format from a full refresh, which could throw an error
  and leave duplicate entries (issue #78).
• %Super and Constructor Checks on Interfaces - Classes whose parent is an
  interface are no longer told to call %Super or add a constructor.
• Deleting an Unused Local Ate a Character - The quick fix no longer removes
  the first character of the following line.
• Connect DB Error Messages - Validation and connection errors in the Connect
  DB dialog now use AppRefiner's own message dialog, owned by the Connect DB
  window.
• Prompt for DB Reopening After Disconnect DB - With "Prompt for DB" on, the
  connect dialog now opens automatically only once per Application Designer.
  Disconnecting no longer brings it straight back; use Database: Connect to DB
  to reconnect.


VERSION 1.3.2
=============

*** PLEASE READ: RESTART APPLICATION DESIGNER ***
-------------------------------------------------

This release updates the AppRefiner integration running inside Application
Designer. Close and reopen any Application Designer that was already open —
until you do, the hook-unload and related fixes below aren't active.


NEW FEATURES
------------

• Stronger Compiler Errors - The unified "Compiler errors" check (on by
  default) now also flags code Application Designer won't compile: functions
  and methods that don't return a value on every path, Break/Continue outside
  a loop, bare Return in a value-returning routine, a return value where none
  is allowed, return expressions of the wrong type, duplicate class members,
  missing property get/set bodies, assignment to a constant, %This outside an
  App Class, subclass constructors that never assign %Super, private/protected
  member access, non-Boolean conditions on If/While/Repeat-Until, and unknown
  fields on the current or referenced record (including bare field names in
  record PeopleCode before App Designer expands them to REC.FIELD). Still one
  toggle, one pass, no extra setup.
• Unload Hook on Close - Closing AppRefiner detaches and unloads the hook DLL
  from every attached Application Designer process, so you can replace or
  delete the install without first closing every App Designer window.
• Smarter Record/Field Return Types - CreateRecord, GetRecord, and GetField
  now carry the identity of the definition you pass in, so later member access
  is checked against the right record or field shape.
• Grid Column Types - Accessing a grid column (including dynamic names) is
  treated as a GridColumn for type checking and autocomplete, instead of
  looking like an unknown property.


BUG FIXES
---------

• SQL Server Connectivity - Tools Release lookup, open-target queries, field-
  type casts, and several queries that needed bound parameters or properly
  declared variables now work correctly against SQL Server databases.
• Offline App Class Checks - Invalid application-class existence checks that
  need a live database connection no longer report false errors when you're
  editing without one.
• Buffer REC.FIELD vs Field Objects - Bare buffer REC.FIELD is treated as the
  field's value (implicit .Value) when used as a scalar, matching the compiler,
  while Field objects from &rec.FIELD, Record.REC.FIELD, and GetField stay
  Field and require .Value for numbers and similar. Intermediate REC.FIELD
  chains (e.g. REC.FIELD.AriaAttributes) still resolve as Field. Autocomplete
  shows Field(Number) for record members.
• RECORD.FIELD Under Default Record - Field inference for RECORD.FIELD under
  default-record PeopleCode no longer goes wrong.
• Definition Keywords as Fields - Keywords that refer to definitions are no
  longer mis-inferred as record fields.
• Convert If ↔ Evaluate Fall-Through - Conversion now uses the same exit-mode
  analysis as the new return-path checks, so Break fall-through is detected
  more reliably.
• Hook Detach Cleanup - Combo-box buttons and subclasses are cleaned up when
  the hook unloads, so Application Designer isn't left with orphan UI from
  the previous AppRefiner session.
• Fold State After Expand - Expanding all folds now clears the remembered
  collapsed paths, so a save no longer re-collapses regions you just expanded
  (issue #76).


VERSION 1.3.1
=============

BUG FIXES
---------

• Missing Semicolon on Top-Level Code - A top-level "Local &x = value"
  statement is executable code, not a declaration, so a missing semicolon on
  it is now reported like any other statement (when it isn't the last one).
• Redeclared Variable Accuracy - A function's local is no longer falsely
  flagged as already declared when a same-named program variable is declared
  below the function, and a local that shadows a Global or Component variable
  declared above it is now correctly reported.
• Unresolved Field Types - Assigning to or from an unresolved record field's
  .Value no longer reports a false type error; an unresolved field type is now
  treated as "any" in both directions.
• Extract Function Placement - A newly extracted top-level function is now
  grouped at the top of your existing functions, instead of being dropped just
  above the first line of main code (below existing functions, variables, and
  constants).
• Instance Variables via %This - Reading an instance variable through %This
  (for example %This.MyVar, without the &) is no longer wrongly flagged as an
  unknown property of the class.
• Missing Abstract Members No Longer a Compiler Error - Unimplemented abstract or
  interface members no longer trip the "Compiler errors" indicator, since they
  don't actually stop a program from compiling. They now have their own opt-in
  "Missing abstract implementations" styler you can enable when you want the
  reminder (with the same "implement missing members" quick fix).


VERSION 1.3.0
=============

*** PLEASE READ: RESTART APPLICATION DESIGNER ***
-------------------------------------------------

This release updates the AppRefiner integration running inside Application
Designer. Close and reopen any Application Designer that was already open —
until you do, the multi-instance and autocomplete fixes below aren't active.


NEW FEATURES
------------

• Instances Tab - See every Application Designer session AppRefiner is
  tracking — database, Tools version, open editors — and connect, disconnect,
  or bring one to the front. No more guessing which window a button acts on.
• Oracle LDAP - Connect to Oracle via LDAP (contributed by NoodleSploder)
• tnsnames.ora IFILE Support - Aliases defined in IFILE-included files now
  appear in the connection list.
• Faster Connect Dialog - Connection lists load in the background, so the
  dialog opens instantly.
• Undeclared Function Detection - Functions that aren't built in, declared, or
  defined above their first use are underlined as you type. Press Ctrl+. to
  import the declaration from your function cache (no database needed), search
  for it, or move a below-defined function above its caller automatically.
• Function Name Autocomplete - Ctrl+Space on a plain identifier lists every
  function you can call there — defined, declared, and builtin — and typing (
  brings up its signature call tip.
• Capture-Result Quick Fix - "Value must be assigned to a variable" errors
  offer a Ctrl+. fix that captures the result into a new local variable,
  correctly typed and named for you.
• Redesigned Snapshot History - Pick a snapshot and instantly see its diff
  against your current code side by side, with per-row change counts and
  one-click copy of the old code or a unified diff. Reverting snapshots your
  unsaved edits first, so nothing is ever lost.
• Message Catalog - Hover any MsgGet-style call to see the message, severity,
  and explain text. Ctrl+Space inside the arguments opens a searchable browser
  that fills in the numbers and text for you — and helps you pick a valid free
  number when planning a new message.
• Extract Local Variable - Select any expression and pull it out into a new,
  correctly typed local declared just above the statement. The type is inferred
  even without a database connection, and when the expression appears more than
  once you can replace every occurrence at the same time.
• Inline Variable - Place the cursor on a local variable to fold its value back
  into each place it's used and remove the declaration. AppRefiner refuses when
  inlining would change behavior — a side-effecting initializer read more than
  once, or a value that changes before it's used — so the result always means
  the same thing.
• Convert If ↔ Evaluate - Turn an If/Else-If chain into an Evaluate statement,
  or an Evaluate back into an If, with one command that picks the direction from
  where your cursor sits. Break semantics, When-Other, and stacked-When "Or"
  conditions are all handled, and it refuses the cases that can't convert
  cleanly rather than changing your logic.
• Extract Function/Method - Select a run of statements and pull them into a new
  function — or a private method when you're in an App Class. AppRefiner figures
  out which variables need to be passed in, lets you pick one to return, and
  turns any additional outputs into "out" parameters, then replaces the
  selection with a call to the new routine. It refuses selections it can't move
  safely, such as those containing a Return.
• Statement Number Margin - Optionally repurpose Application Designer's
  line-number margin to display PeopleCode statement numbers instead. Locate the
  statement from a stack trace by scrolling to it, rather than using App
  Designer's Goto-by-statement dialog. Turn it on in General Settings.
• Unified Compiler Error Check - The fourteen separate checks that flagged code
  that won't compile now live under a single "Compiler errors" toggle, on by
  default — so you see everything that's wrong at once instead of enabling each
  one by hand. It covers syntax errors, type errors, missing semicolons,
  redeclared variables, undefined variables (in App Classes), class name
  mismatches, invalid application classes, unimported classes, ambiguous class
  references, invalid member access, undeclared functions, missing method
  implementations, missing constructors, and unimplemented abstract members.
  All of their quick fixes are preserved, and everything now runs in a single
  pass over your code. (Undefined-variable flagging outside App Classes remains
  its own optional style, where it's a code smell rather than a compile error.)


PARSER ENGINE OVERHAUL
----------------------

The PeopleCode parser behind linting, styling, and refactoring was deeply
audited this release (~50 fixes, now guarded by an automated test suite).

• Valid Code Parses Cleanly - Fixed false errors on legal PeopleCode: `&y-1`
  without spaces, `Not` with comparisons, keyword-named methods, mid-line REM,
  case-differing implementations, and more. If App Designer accepts it,
  AppRefiner should too.
• One Typo, One Error - Mistakes stay contained while you type: a typo or
  missing End-If no longer blanks styling for the rest of the class or
  swallows the code below it, and error messages point at the actual problem
  ("'End-If' has no matching 'If'") instead of flooding the list.
• No Crashes or Hangs - Input that could previously crash AppRefiner or pin a
  background thread at 100% CPU now just reports an error and moves on.
• More Accurate Analysis - Property getters, annotations, and Catch variables
  are now fully visible to linters, rename, and unused-variable detection, and
  quick fixes/refactors always edit exactly the text they should.


RELIABILITY & MULTI-INSTANCE FIXES
----------------------------------

A large overhaul of how AppRefiner talks to Application Designer, resolving a
class of intermittent issues — especially with multiple instances open.

• Editor Features No Longer Stop Working - Editors opened mid-session no
  longer silently lose autocomplete, the AppRefiner button, or the minimap —
  they stay fully functional for the life of the session.
• Instant Editor Setup - Editors are wired up the moment they open — hints and
  highlights included — instead of waiting for your first click. Editors
  already open when AppRefiner starts are picked up immediately.
• Enhanced Editor Without Restarting - Attaching to a running Application
  Designer no longer requires restarting it for the enhanced editor; it loads
  as soon as you close the open editors.
• Correct Instance Routing - Autocomplete, tooltips, call tips, and save
  tracking always land in the editor that triggered them — even when switching
  quickly or running several Application Designers.
• Wrong Values and Garbled Text - Eliminated the race conditions behind
  occasional wrong autocomplete values, garbled tooltips, and stale content.
• Auto-Connect Prompt Placement - The startup connect prompt appears on the
  Application Designer you actually switch to, instead of hiding behind other
  windows.
• Session Lifecycle - Closing editors or exiting an Application Designer no
  longer leaves stale state behind — reopening and relaunching just work.


BUG FIXES
---------

• Inlay Hints Survive Saving - Parameter name hints and error highlights no
  longer disappear when you save.
• Accurate Enhanced Editor Status - The Instances tab's "Enhanced" column now
  reflects whether the enhanced editor is actually loaded, instead of being
  decided by your Tools version.
• Autocomplete Doubling - Accepting a suggestion after typing part of a name no
  longer duplicates the text (e.g. "&varvariable"), including in files that
  contain non-ASCII characters.
• Lingering Error Highlights - Squiggles now clear automatically once the code
  is valid again — no more saving or refreshing to clean them up.
• Class Autocomplete Semicolon - A trailing ";" is only added when completing a
  class inside an import statement, not mid-expression.
• Find & Replace - "Replace All" now searches the correct term when used more
  than once in a session, and no longer inserts stray characters.
• Signature Updates - Added undocumented Json* methods, corrected SQLExec and
  Hash.SetValue() types, handled "@" references in built-in signatures, and
  capitalized all system variables.
• "Out" on Function Parameters - Marking a plain Function parameter with "Out"
  is now flagged as an error — Function parameters are always passed by
  reference, so "Out" only applies to App Class method parameters. This matches
  what the PeopleCode compiler rejects.
• Parameters on Declare Function ... PeopleCode - A "Declare Function ...
  PeopleCode" declaration that carries a parameter list is now flagged, since
  its parameters are implicit to the referenced record field event and aren't
  allowed here. Library (DLL) declarations with Ref/Value parameters are
  unaffected.
• New Class Members Recognized Immediately - Methods and properties you add to
  the class you're editing — via Extract Function/Method or by hand — are no
  longer flagged as unknown until you save and edit a second time. The member
  access check now sees the live, unsaved class.


PERFORMANCE
-----------

• Responsive Editing - Stylers now run asynchronously, keeping the editor
  responsive while analysis happens in the background.
• Fewer Cross-Process Reads - AppRefiner reads far less document data while you
  type, reusing cached parse results when the document hasn't changed.
• Member Access Caching - Member access validation is memoized, with automatic
  invalidation on save or when switching Application Designer sessions.
